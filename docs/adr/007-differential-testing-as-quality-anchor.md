# ADR-007：差分对拍 + golden 字节为质量锚点

状态：已采纳 ｜ 日期：2026-11-22

## 背景
C++ 源码不在包内（仅 DWARF 二进制），Go 行为正确性的唯一权威判据是"与原版一致"。

## 决策
1. 每阶段交付物先以"挂原版其余组件"模式运行，逐字节 diff
2. 原版真实流量采样存 `ltcq-go/reference/captures/` 作为 golden 文件，编解码测试永久引用
3. netframe 内置对比模式（编译开关/子命令），从 M2 起一键回归
4. 对拍 harness 是正式交付物，不是一次性脚本

## 理由
1. 原版进程就是活的规格说明（可执行验收）
2. golden 字节让帧兼容性在 CI 里永久守住

## 后果
+ 每个里程碑都有机器可验证的出栏标准
- 需要原版四件套环境长期可用（Windows exe 基准，已就绪）
- 黑盒行为差异（如浮点边缘）需人工裁决记录进 ADR
